# Подбор площадок

Страница `/placements` (пункт меню «Подбор площадок»). Пользователь описывает, что рекламирует: «шиномонтаж в Уфе, клиенты — автомобилисты», «группа про Nintendo Switch, хочу больше подписчиков». Город — необязательное поле, его стоит указать для местного бизнеса. Если город не выбран, DeepSeek определит его по описанию; если бизнес не местный, поиск идёт по всей России.

Результат — до 30 сообществ VK в двух блоках:
- **«Под вашу аудиторию»** (для своей группы — **«Похожие и тематические сообщества»**) — сообщества про интересы аудитории;
- **«Общегородские паблики»** — новости, подслушано, афиши. Подходят любому местному бизнесу, поэтому показываются только при городе.

По каждому сообществу:
- подписчики, типичные просмотры поста и их доля от подписчиков, маркированная реклама в неделю;
- **причина** — почему подходит, по содержанию постов;
- **«Рекламируются»** — кто размещает рекламу в этом сообществе;
- контакты сообщества и ссылка «Написать».

Сообщества с мёртвой аудиторией — меньше 100 просмотров или меньше 0,3% подписчиков — стоят в конце блока с пометкой «мало просмотров». Над таблицами — фильтр размера (до 50 тыс. / 50–500 тыс. / больше 500 тыс.) и сортировка. Отмеченным «в подборку» можно ввести цену: CPM считается по строке и по всей подборке.

Параметры лежат в адресе страницы (`brief`, `cityId`, `city`), поэтому перезагрузка открывает тот же подбор. Пока подбор идёт (обычно 45–70 секунд), страница показывает этапы по типичному времени: сервер прогресс не сообщает.

Фича включается переключателем «Подбор площадок» в админке (вкладка «Настройки»): выключено / только администраторам / всем. От режима зависят пункт меню, маршрут страницы и все запросы `/api/placements/*`: выключенной фиче API отвечает 403 `FEATURE_OFF`. В `/api/account/me` режим приходит полем `placementsEnabled`.

## Как идёт подбор

Один подбор — `GET /api/placements/search?brief=&cityId=`. Код: `api/src/services/placementSearchService.ts`, работа с DeepSeek — `api/src/services/placementClassifier.ts`.

1. **Задача.** DeepSeek читает описание и возвращает:
   - тип: бизнес или сообщество;
   - нужен ли город и какой;
   - аудиторию одной фразой;
   - 12–16 запросов для поиска сообществ по интересам аудитории;
   - слова, по которым узнаются конкуренты, — только для бизнеса. Для сообщества похожие группы — лучшие площадки, конкурентов у него нет.
2. **Город.** Выбранный в подсказках (`GET /api/placements/cities?q=`, `database.getCities` с `lang=ru`; подсказка запоминается в Redis на 30 дней) или названный моделью — тогда берётся первая подсказка VK. Если модель считает бизнес местным, а города нет, в ответе `cityMissing: true`, и страница просит его указать.
3. **Поиск.** `groups.search` **токеном пользователя** — сервисный ключ VK этот метод не принимает, без токена подбор отвечает 401 `VK_TOKEN_REQUIRED`. Запросы:
   - запросы модели — с `city_id`, если город есть;
   - при городе ещё слова городских пабликов («подслушано», «типичный», «новости», «инцидент», «афиша», «чп») с `city_id` и название города без фильтра.

   Запросы идут по 4 параллельно через общую очередь: не больше 3 запросов к VK в секунду на пользователя.
4. **Кандидаты.** `groups.getById` с описанием и контактами. Остаются открытые сообщества от 1 000 подписчиков при городе и от 3 000 без него: 240 крупнейших из поиска по интересам и 30 из поиска городских пабликов.
5. **Отбор по названиям.** DeepSeek оценивает кандидатов пачками по 60 (до 5 параллельно): насколько подходит (0–2) и конкурент ли. На следующий шаг идут 30 лучших не-конкурентов, у которых в названии нет слов конкурентов. Порядок: сначала оценка, потом размер.
6. **Посты.** `execute` пачками по 5 `wall.get` (100 последних постов), по 3 пачки параллельно. Больше 5 стен VK в один ответ не помещает («response size is too big»); если не влезли и 5, пачка делится пополам, а стена, которая не влезла одна, остаётся без постов.
7. **Вердикт по постам.** DeepSeek получает по каждому сообществу 6 последних обычных постов и 4 последних рекламных (по 180 символов), пачками по 5, до 8 параллельно. Возвращает: оценку, блок («тема», «город» или «не подходит»), причину, кто рекламируется, конкурент ли. Сообщества «не подходит», с оценкой 0 и конкуренты отбрасываются.
8. **Метрики** считают те же функции, что у [проверки перед рекламой](ad-check.md), без ночных срезов:
   - типичные просмотры — медиана текущих просмотров постов старше 3 дней;
   - разброс — 25-й и 75-й процентили;
   - реклама — по маркировке; если 100 постов не покрывают 30 дней, она считается по покрытым дням.
9. **Порядок строк:** живые сообщества, затем блок темы перед городским, затем оценка модели, затем просмотры.

Во всех подсказках модели есть общие правила:
- площадка — это медиа, где можно купить пост: паблик, новости, афиша, подслушано, сообщество по интересам, блог, барахолка;
- страница компании, магазина, бара, студии, салона, мастера, застройщика — не площадка, даже если аудитория похожа;
- для сообщества похожие группы получают высшую оценку.

В DeepSeek уходят только описание задачи, публичные названия, описания и тексты постов сообществ. Данных пользователей там нет. Тексты очищаются от половинок разрезанных эмодзи (`wellFormed` в `deepseekClient.ts`): иначе DeepSeek отвечает 400. Сетевой сбой, 429 и 5xx повторяются один раз через секунду.

## Без DeepSeek

Запасной путь срабатывает, когда:
- нет ключа или `PLACEMENT_AI_ENABLED=0`;
- исчерпан суточный бюджет;
- модель не разобрала описание.

Как он работает:
- **Запросы:** описание целиком и его слова от 4 букв.
- **Тип:** выбранный город делает задачу местным бизнесом, без города — сообществом.
- **Отбор и вердикты** — правила `ruleVerdict`. Страница компании (салон, магазин, студия, ООО, ИП, «под ключ», «на заказ», бар, кафе, клуб, мастер) не подходит. При городе в названии или описании должно упоминаться место. Причины и рекламодателей у таких строк нет.

Если модель пропустила в ответе часть сообществ, им тихо ставятся правила. Если запрос к модели упал, в ответе `aiUsed: false`, и страница показывает предупреждение.

## Лимиты и кэш

Лимиты и кэш живут в Redis; без Redis подбор отвечает 503.

- **Подборов в сутки на пользователя:** без тарифа `PLACEMENT_DAILY_LIMIT_FREE` (1), с тарифом `PLACEMENT_DAILY_LIMIT_PAID` (20). Считаются разные сочетания «описание + город», регистр и лишние пробелы не важны. Повтор того же подбора лимит не тратит. Подбор списывается после успешного ответа, упор в лимит — 429 `PLACEMENT_LIMIT`.
- **Без тарифа** подробности видны у первых `PLACEMENT_FREE_ROWS` (5) строк общего порядка. Остальные приходят без метрик, причин и рекламодателей (`locked: true`), под таблицей — призыв к тарифу.
- **Результат подбора** кэшируется на `PLACEMENT_SEARCH_CACHE_TTL_MS` (24 часа) для всех пользователей. Поле `cached` говорит, взят ли ответ из кэша.
- **Подборов с DeepSeek на весь сервис:** `PLACEMENT_AI_MAX_PER_DAY` (500) в сутки, сверх — запасной путь. Подборы из кэша в бюджет не входят. Один подбор — около 50 тыс. токенов, порядка 1,5–2 ₽.

## Статистика

События активности:
- `placement_search` — label `город|описание|ai или rules|строк`; город пуст, если подбор без города;
- `placement_limit` — упор в лимит;
- `placement_select` — label — id сообщества; отмеченное «в подборку» сообщество попадает в ночные срезы с происхождением `placement`;
- `placement_open` — `vk` / `contact` / `message`;
- `placement_price` — первая введённая цена за показ страницы;
- `placement_filter` — фильтр размера `small` / `medium` / `large`;
- `placement_paywall_click` — `rows` под таблицей или `limit` в сообщении о лимите.

Расход DeepSeek по дням пишется в Redis-хэш `socstat:placements:ai:stats:<дата>`: подборы, подборы со сбоями модели, запросы, неудачные, токены, миллисекунды; хранится 120 дней. Админов в нём не отделить.

Всё это собирает `api/src/services/placementStatsService.ts` в раздел `placements` [выгрузки аналитики](admin-export.md). Админы из событий исключены.

## Ограничения

- **Модель ошибается.** Изредка пропускает страницу компании («Натяжные потолки», «Дизайнер интерьера») или ставит в общегородские развлекательный комплекс. Причина у строки помогает заметить это сразу.
- **Порядок по просмотрам** поднимает наверх крупные медиа. Для небольшой группы нужен фильтр «до 50 тыс.».
- **Подбор идёт 45–70 секунд:** больше половины времени — загрузка постов.
- **Немаркированную рекламу не видно:** «Рекламируются» и реклама в неделю — нижняя оценка. Просмотры — не уникальные зрители.
- **Собачек и истории подписчиков в подборе нет.** История копится только у сообществ, отмеченных «в подборку».

## Код

- `api/src/routes/placements.ts` — маршруты, переключатель фичи, проверка Redis.
- `api/src/services/placementSearchService.ts` — город, запросы, кандидаты, посты, строки, порядок, лимиты, кэш, счётчики DeepSeek.
- `api/src/services/placementClassifier.ts` — подсказки модели, разбор и проверка ответов, запасные правила.
- `api/src/services/deepseekClient.ts` — запрос к API, очистка текста, повтор, таймаут.
- `api/src/services/vkSourceLoader.ts` — запросы VK и разбор стены, общие с проверкой перед рекламой.
- `api/src/services/placementStatsService.ts` — статистика для выгрузки.
- Тесты: `api/src/services/placements.test.ts`.
- `src/pages/PlacementsPage.tsx` — страница; стили `.placements-*` в `src/styles.css`; события интерфейса — `trackPlacementEvent` в `src/utils/visit.ts`.

## Настройки

`DEEPSEEK_API_KEY`, `DEEPSEEK_MODEL` (`deepseek-chat`), `DEEPSEEK_TIMEOUT_MS` (25 000), `PLACEMENT_AI_ENABLED` (1), `PLACEMENT_AI_MAX_PER_DAY` (500), `PLACEMENT_DAILY_LIMIT_FREE` (1), `PLACEMENT_DAILY_LIMIT_PAID` (20), `PLACEMENT_FREE_ROWS` (5), `PLACEMENT_SEARCH_CACHE_TTL_MS` (сутки). На проде нужен только `DEEPSEEK_API_KEY` в `api/.env`, остальное — значения по умолчанию.
