# Ночные срезы

Публичные API VK, YouTube и Telegram показывают только текущие счётчики, без истории. Поэтому Socstat сам раз в день сохраняет число подписчиков и счётчики свежих публикаций. Из этих срезов строятся история и прирост подписчиков, рост аудитории в сравнении с конкурентами, направление роста в урезанном отчёте и кривая набора просмотров. Пропущенный день восстановить нельзя.

Код: `api/src/services/snapshotService.ts`, вспомогательные расчёты — `api/src/services/snapshotUtils.ts`, маршруты — `api/src/routes/snapshots.ts`.

## Что сохраняется

- `ChannelSnapshot` — один документ на источник и дату: подписчики, название, для YouTube ещё общее число просмотров и видео. Для VK также флаг `postsCollected` и счётчик попыток `postsAttempts`.
- `PostSnapshot` — счётчики каждой публикации за последние `SNAPSHOT_POST_WINDOW_DAYS` дней (по умолчанию 7) на дату среза: просмотры, реакции, комментарии, пересылки и сколько часов прошло с публикации.
- `SnapshotDay` — покрытие дня: сколько источников ожидалось, сколько снято, у скольких VK-сообществ ещё нет постов и почему проход остановился. Показывается в админке.

Дата среза считается по Москве (`Europe/Moscow`), независимо от часового пояса сервера.

## Какие источники попадают в срез

Список собирается заново перед каждым проходом (`collectSnapshotSources`) и только растёт — источник, однажды попавший в него, снимается дальше бессрочно:

| Источник | Платформы |
| --- | --- |
| Сообщества и каналы на дашбордах (`SavedGroup`) | все |
| VK-сообщества, удалённые с дашборда (бесплатные и бонусные остаются с `isTracked: false`) | VK |
| `SnapshotSource`: VK-сообщества, которые хоть раз открывали в аналитике (полной или урезанной), `note: 'viewed'` | VK |
| `SnapshotSource`: добавленные вручную скриптом `snapshots:seed`, `note: 'seed'` | все |
| Наборы конкурентов (`CompetitorSet`): исходное сообщество и конкуренты | все |
| Сохранённые подборки сравнения и публикаций (`ComparisonCollection`) | VK |

Telegram из открытых и сравниваемых источников сознательно не добавляется: все запросы Telegram идут через одну личную MTProto-сессию, и бесконечный рост списка для неё опасен.

## Расписание

Планировщик (`startSnapshotScheduler`) включается переменной `SNAPSHOTS_ENABLED` (по умолчанию только в production). Каждые 15 минут после `SNAPSHOT_START_HOUR` (по умолчанию 3:00 МСК) он запускает проход, который снимает только источники без среза за сегодня. Поэтому прерванный проход — лимит, перезапуск, ошибка — сам продолжается в следующий тик, а повторные тики в течение дня почти ничего не делают. Одновременно проход выполняет только одна реплика API: блокировка в Redis на 2 часа.

## ВКонтакте

1. **Подписчики:** `groups.getById` с полем `members_count`, пачками по 400 сообществ.
2. **Публикации:** отдельным шагом один `wall.get` (100 последних записей) на сообщество, в срез идут записи моложе окна. Неудачный запрос повторяют следующие проходы дня, до `SNAPSHOT_POST_MAX_ATTEMPTS` попыток (по умолчанию 5), не снимая подписчиков заново. Закрытая, удалённая или заблокированная стена (коды 7, 15, 18, 30) считается окончательной ошибкой и не повторяется.

### Ключи доступа

Запросы идут ключами в таком порядке:

1. **Сервисный ключ приложения** (`VK_SERVICE_KEY`) — запросы от имени приложения, с собственной квотой, пауза 210 мс (лимит VK — 5 запросов в секунду для приложения до 10 000 пользователей).
2. **Токены администраторов** (`ADMIN_VK_IDS`) — пауза 350 мс (3 запроса в секунду на пользовательский токен).
3. **Токены служебных аккаунтов** (`SNAPSHOT_VK_IDS`) — например, отдельные аккаунты, которые дали согласие; токен появляется после входа этим аккаунтом в Socstat.

Токены обычных пользователей не используются никогда. При ошибках 5 (недействительный токен), 6 (слишком много запросов после повторов), 14 (капча) и 29 (суточный лимит метода) ключ выбывает до конца прохода, а тот же запрос повторяется следующим ключом. Если закончились все ключи, проход останавливается с причиной `VK_KEYS_EXHAUSTED` («лимит всех VK-ключей» в админке) без траты попыток — следующий тик начнёт заново с первого ключа. Нет ни одного ключа — `VK_TOKEN_REQUIRED`.

Ограничение: стену закрытого сообщества сервисный ключ не читает, поэтому у таких сообществ сохраняются подписчики, но не посты.

Проверить сервисный ключ (отдаёт ли подписчиков и просмотры постов):

```bash
npm run snapshots:check-vk-key --workspace @socstat/api -- 125792332
```

## YouTube

Для каждого канала — сведения о канале и видео за окно через YouTube Data API (`YOUTUBE_API_KEY`). Без ключа проход по YouTube останавливается с `YOUTUBE_API_KEY_REQUIRED`.

## Telegram

Не больше `SNAPSHOT_TELEGRAM_MAX_PER_RUN` каналов за проход (по умолчанию 200) с паузой `SNAPSHOT_TELEGRAM_DELAY_MS` (3 секунды) между каналами, чтобы общая MTProto-сессия оставалась свободной для запросов пользователей. Лимит, отсутствие настроек или недействительная сессия останавливают Telegram до следующего тика.

## Как срезы используются

- **История подписчиков** — `GET /api/snapshots/history?platform=&id=&days=`: точки `{ date, subscribers, change }`.
- **Прирост за период** — от среза на дату начала периода до текущего числа подписчиков (`getSnapshotGrowth`): дашборд, сравнение с конкурентами, направление роста в урезанном отчёте VK, когда у VK нет статистики.
- **Кривая набора просмотров** — `GET /api/snapshots/posts?platform=&id=&days=`: просмотры каждой публикации через 24/48/72 часа интерполяцией между ночными срезами и медиана по источнику (не меньше 3 публикаций).
- **Покрытие** — `GET /api/snapshots/coverage?days=` (только админ), вкладка в админке.

Доступ к истории и кривой — с активным тарифом или для бонусного источника пользователя.

## Ручные операции

```bash
# дособрать сегодняшний срез вручную
npm run snapshots:run --workspace @socstat/api
# добавить источники из файла, по одному на строку
npm run snapshots:seed --workspace @socstat/api -- telegram channels.txt
```

Формат файла для `snapshots:seed`: `@username` или ссылка `t.me` для Telegram, channel ID `UC…` для YouTube, числовой ID группы для VK.
