# Краткий отчёт и бесплатный полный отчёт без доступа

Когда пробный период или тариф закончились, человек всё ещё может что-то посмотреть, а не упирается сразу в оплату.

## Что видит пользователь без доступа

- **ВКонтакте** — краткий отчёт за последние 7 дней (`preview` в ответе `GET /api/analytics/community/:groupId`, собирает `api/src/services/analyticsPreview.ts`). Подписчики, число публикаций и лучший пост открыты, остальные блоки размыты, вместо настоящих цифр — заглушки.
- **YouTube** — заглушка «С возвращением! Доступ к аналитике закончился» с предложением бесплатного полного отчёта.
- **Telegram** — та же заглушка, но без пропуска: аналитика Telegram только на тарифе, заглушка зовёт смотреть ВКонтакте.

Баннер над кратким отчётом и заглушки сначала предлагают бесплатный полный отчёт, тариф — второй кнопкой («Тариф от 699 ₽ в месяц», цена из `/api/payments/plans`).

## Бесплатный полный отчёт (пропуск)

- Раз в 30 дней пользователь без доступа может открыть полный отчёт по одному сообществу VK или каналу YouTube. Пропуск включается только кнопкой «Открыть полный отчёт бесплатно» / «Открыть этот канал бесплатно», сам не тратится.
- После включения этот источник 24 часа открыт как с тарифом: любой период до 90 дней, «Обновить», разделы «Сводная», «Аудитория», «Посты», история подписчиков и кривые просмотров по срезам. Над отчётом — плашка «Открыто по бесплатному пропуску до …».
- Конкуренты пропуском не открываются, остаются на тарифе.
- Пока пропуск доступен, клик по закрытому блоку краткого отчёта не уводит на оплату, а прокручивает к баннеру и подсвечивает его.
- Когда пропуск потрачен, баннер пишет, когда будет следующий, а если он ещё действует на другом источнике — даёт вернуться к нему.

## Как устроено

- `User.reportPass` — платформа, id источника (VK без минуса), название и время включения `usedAt`.
- `api/src/services/reportPass.ts` — правила (`getReportPassState`: `available` / `active` до `usedAt + 24 ч` / `used` до `usedAt + 30 дней`) и включение `activateReportPass` одним атомарным обновлением: двойной клик или две вкладки не потратят два пропуска.
- `POST /api/analytics/report-pass` с `{ platform, sourceId, sourceName }` (`api/src/routes/analytics.ts`). С активным доступом — 409 `ACCESS_ACTIVE`, при потраченном пропуске — 409 `REPORT_PASS_UNAVAILABLE`.
- Доступ проверяют `hasReportPassAccess` в `api/src/middleware/access.ts`: в `GET /api/analytics/community/:groupId` (тогда в ответе `reportPass.expiresAt`) и в `api/src/routes/snapshots.ts`.
- Состояние пропуска приходит в `/api/account/me` как `user.reportPass`; `null`, когда доступ активен.
- Фронт: баннер — `src/components/AnalyticsPreview.tsx`, заглушки — `src/components/AccessLock.tsx`, плашка и общие функции — `src/components/ReportPass.tsx`, включение — `activateReportPass` в `src/pages/AnalyticsPage.tsx`.

## Статистика

Блок «Краткий отчёт без доступа» во вкладке «Посещаемость» и раздел `preview` [выгрузки](admin-export.md):

- `analytics_preview` — открыли краткий отчёт, `preview_unlock` — кликнули по закрытому блоку (label — какому);
- `report_pass_used` — включили пропуск (label — id источника), `passPaidUsers` / `passRevenue` — оплатили после включения;
- полные отчёты по пропуску пишутся как `analytics_view` с label `pass`;
- `access_lock` — видели заглушку YouTube или Telegram (label — платформа), в статистике `lockViewers`.

## Ограничения

- Пропуск привязан к id источника из отчёта. Если сообщество открыли по короткому имени в ссылке, отчёт перезагружается по числовому id.
- Telegram пропуском не открывается: без доступа там закрыта вся страница вместе с поиском.
- Админ видит пропуск только с включённой проверкой ограничений тарифа.
