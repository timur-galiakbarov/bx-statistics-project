# Кэш API и расход памяти

API временно хранит полученные данные в памяти, чтобы повторное открытие отчётов не вызывало лишних запросов. Общий класс — `api/src/services/ttlCache.ts`. Его используют аналитика VK, клиенты YouTube и Telegram, а также локальные копии кэшей Redis через `api/src/services/redisJsonCache.ts`.

## Очистка и ограничения

- Проверка просроченных записей выполняется раз в **5 минут**. Для этого не нужны запросы к внешним сервисам или базе.
- Срок хранения задаёт каждый сервис отдельно. Например, отчёт аналитики VK хранится час. Чтение записи не продлевает этот срок.
- Просроченный результат сразу перестаёт выдаваться, даже если очередная очистка ещё не наступила. В памяти он может оставаться до ближайшей проверки.
- Каждый экземпляр кэша хранит не более **200 записей**. При добавлении в заполненный кэш сначала удаляются просроченные записи, затем, если место всё ещё нужно, запись, которую дольше всего не читали и не обновляли.
- Проверка запускается при первой записи и останавливается, когда очередная очистка обнаруживает пустой кэш. Таймер не мешает завершению процесса API.

Например, пользователь последовательно открыл 1000 разных отчётов. В кэше аналитики останется не более 200 записей. Если открыть вытесненный отчёт снова, API заново соберёт данные. Для локальной копии кэша Redis сначала проверяется Redis: удаление из памяти API не удаляет запись из Redis и не меняет её срок хранения.

Раньше просроченная запись удалялась только при повторном запросе того же ключа. При просмотре множества разных сообществ данные могли оставаться в памяти до завершения процесса.

## Настройки и границы

Интервал очистки и стандартный лимит заданы в `TtlCache`. Третий аргумент конструктора позволяет задать другой положительный целый лимит для отдельного экземпляра; существующие сервисы используют 200. Переменных окружения для этих настроек нет.

Лимит относится к числу записей каждого экземпляра, а не к байтам или общей памяти API. Размер отчётов и медиа различается, поэтому это не гарантирует определённого расхода RAM. Redis, данные текущих запросов и другие структуры памяти этим лимитом не ограничиваются.

## Проверка

`api/src/services/ttlCache.test.ts` проверяет очистку через пять минут без повторного чтения ключей, сохранение свежих данных, повторный запуск очистки после опустошения кэша, ограничение количества и порядок вытеснения. Запуск из корня проекта: `node --import tsx --test api/src/services/ttlCache.test.ts`.

После выкладки нужно сравнивать память контейнера API при похожей нагрузке. Найденное накопление устранено, но долю кэша в прежнем расходе RAM без отдельных замеров установить нельзя.
