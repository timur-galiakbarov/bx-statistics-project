# Уведомления в браузере

Socstat присылает web push-уведомления об окончании доступа: пробного или оплаченного. Других рассылок пока нет. Уведомление приходит, даже если сайт закрыт, — нужен только запущенный браузер.

## Как пользователь подписывается

Сначала свой баннер, потом системный запрос браузера. Системное окно открывается только после «Да, напомнить»: если человек сразу нажмёт в нём «Блокировать», спросить снова будет нельзя.

Баннер (`PushPrompt`) показывается на любой странице приложения, если выполнены все условия:

- у пользователя активный доступ — пробный (7 дней после регистрации) или оплаченный;
- на дашборде есть хотя бы один канал. Новичок видит баннер сразу после добавления первого канала, в том же визите;
- прошло 6 секунд после того, как условия выполнились;
- браузер поддерживает пуши, на сервере заданы ключи VAPID, а пользователь ещё не отвечал браузеру на запрос разрешения;
- за последние 3 недели он не нажимал «Не сейчас».

Пока идёт пробный доступ, текст говорит о пробном доступе, потом — об оплаченном. После согласия регистрируется service worker `public/sw.js`, а подписка браузера сохраняется на сервере и привязывается к аккаунту. Один пользователь может быть подписан из нескольких браузеров.

Второй путь — блок «Уведомления в браузере» в профиле: включить и выключить можно в любой момент, независимо от доступа.

## Когда приходят уведомления

Планировщик проверяет подписчиков каждые 15 минут и отправляет уведомления только с 10:00 до 21:00 по Москве. Для каждой даты окончания доступа — не больше трёх уведомлений, каждое по одному разу:

| Этап (`kind`) | Когда | Заголовок |
| --- | --- | --- |
| `expiry_before` | за 3 дня и меньше до окончания | «Пробный доступ / Доступ к socstat заканчивается 30 октября» |
| `expiry_today` | первые сутки после окончания | «… закончился» |
| `expiry_after` | 3–7 дней после окончания | «Ваши каналы продолжают меняться» |

- Уведомление уходит при первой проверке в окне своего этапа: если доступ кончился ночью, «закончился» придёт в 10:00.
- Между двумя уведомлениями одному пользователю — не меньше 20 часов.
- В тексте цена месяца: сохранённая старая для тех, кто уже платил, иначе текущая.
- Клик открывает `/app/account?from=push_<kind>` и записывается; оплата в 7 дней после пуша считается продлением после пуша.
- Push-сервис браузера хранит уведомление 12 часов: если браузер всё это время выключен, оно пропадает. Подписки, которые браузер отозвал (ответ 404/410), удаляются.
- На iPhone Safari показывает пуши только сайтам, добавленным на экран «Домой», поэтому там уведомления почти не доходят.

## Статистика

Блок «Уведомления» в админке и раздел `push` в [выгрузке](admin-export.md): подписчики, показы баннера и ответы на него (событие `push_prompt`: `shown`, `accepted`, `dismissed`, `denied`), отправленные уведомления, клики и продления по каждому этапу.

## Настройки

В `api/.env`:

- `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` — ключи, генерируются один раз: `npx web-push generate-vapid-keys`. Без них пуши выключены целиком: баннер не показывается, в профиле «браузер не поддерживает уведомления», в логе API при старте — `VAPID keys are missing`. **Менять ключи нельзя**: все существующие подписки перестанут работать. На проде ключи заданы 27.10.2026, до этого пуши не работали.
- `VAPID_SUBJECT` — контакт для push-сервисов, по умолчанию `mailto:support@socstat.ru`.
- `PUSH_REMINDERS_ENABLED` — планировщик напоминаний, по умолчанию включён только в production.

После правки `api/.env` контейнер API нужно пересоздать (`docker compose -f docker-compose.prod.yml up -d api`): `docker restart` файл не перечитывает. Тестовое уведомление себе — `POST /api/push/test` (только администратор).

## Код

- `src/components/PushPrompt.tsx` — баннер и переключатель в профиле; условия показа баннера — в `src/App.tsx`.
- `src/utils/push.ts` — подписка браузера, отказ «Не сейчас» на 3 недели (`localStorage`).
- `public/sw.js` — показ уведомления и обработка клика.
- `api/src/routes/push.ts` — `/api/push/config`, `subscribe`, `unsubscribe`, `prompt`, `click`, `test`, `admin/stats`.
- `api/src/services/pushReminders.ts` — этапы, тексты, отправка и планировщик; `api/src/services/pushStatsService.ts` — статистика.
- Модели `PushSubscription` и `PushDelivery` (уникальный индекс по пользователю, этапу и дате окончания — одно уведомление на этап).
