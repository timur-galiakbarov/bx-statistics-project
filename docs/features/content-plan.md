# Контент-план

Раздел для планирования и публикации постов. Сейчас — **этап 4**: календарь и список публикаций, черновики, собственный Telegram-бот пользователя, редактор с markdown, отправка в Telegram и ВК, автопубликация.

## Свой бот у каждого пользователя

Общего бота сервиса нет: каждый пользователь создаёт своего бота в BotFather и добавляет его в свои каналы. Так пользователь контролирует доступ и может отозвать токен в любой момент.

- Один бот на пользователя; каналы привязываются к нему.
- Токен бота вставляется в интерфейсе, проверяется через `getMe` и хранится в MongoDB **в зашифрованном виде** (AES-256-GCM). В API токен никогда не возвращается.
- Серверный ключ шифрования: `CONTENT_PLAN_BOT_TOKEN_KEY` — 32 байта в base64, например `openssl rand -base64 32`. Без ключа подключение ботов и ВК отвечает `503`.
- Замена бота помечает подключённые каналы как «проверить»: новый бот мог не быть в них админом.
- Отключение бота удаляет токен и помечает каналы как неподключённые.

## Доступ

- Фича включается ключом `contentPlan` в «Админка → Настройки → Фичи»: `Выключено / Только администраторам / Всем пользователям`.
- По умолчанию `off`. Для проверки поставьте «Только администраторам».
- В `/api/account/me` приходят `contentPlanEnabled` и `contentPlanMode`. По первому показываются пункт меню и `/content-plan`, по второму — щит «Только для администратора» в меню и плашка в шапке: они видны только в режиме `admins`, а при `all` не показываются.
- API `/api/content-plan` отвечает `403 FEATURE_OFF`, если фича выключена или недоступна пользователю.

## Что работает

- Страница `/content-plan`: календарь на всю ширину, список публикаций и отдельный список всех серверных черновиков. Бот и подключения находятся в окне «Каналы», которое открывается кнопкой в шапке.
- Подключать первую площадку можно в любом порядке: Telegram или ВКонтакте. Написать новый пост можно и без подключённого канала; такой черновик хранится только на текущем устройстве.
- Подключение своего бота:
  1. Откройте `@BotFather`, отправьте `/newbot`, придумайте имя и username.
  2. Скопируйте токен вида `123456:ABC…`.
  3. Вставьте токен в разделе — сервер проверит его через `getMe` и сохранит зашифрованным.
  4. Добавьте бота в канал администратором с правом «Публиковать сообщения».
- Подключение канала: вставьте `@username` или ссылку `t.me/…`; сервер проверяет `getChat` и `getChatMember`.
- Подключение группы ВК: кнопка «ВК» показывает группы, где пользователь администратор (`groups.get?filter=admin`). Пользователь выбирает группу и вставляет **ключ доступа сообщества**, созданный в настройках сообщества: «Управление → Дополнительно → Работа с API → Ключи доступа». Ключ проверяется, шифруется и хранится только на сервере.
- Публикация ВК использует `wall.post` от имени сообщества (`owner_id = -id`, `from_group = 1`). Для поста с фото изображение загружается с пользовательским токеном ВК, а готовое вложение передаётся в `wall.post` с ключом сообщества.
- Редактор: канал, текст с панелью форматирования, предпросмотр, дата и время. Лимит — 4 096 символов для Telegram и 16 000 для ВК.
- «Сохранить черновик», «Запланировать», «Опубликовать сейчас». Для уже запланированного поста основная кнопка называется «Сохранить изменения».
- Автопубликация: планировщик раз в 30 секунд отправляет созревшие посты в Telegram или ВК.
- Статусы: `draft`, `scheduled`, `publishing`, `published`, `failed`; у опубликованного сохраняется ссылка на сообщение, у упавшего — ошибка.

## Календарь, список и фильтры

- В календаре показаны время, площадка, начало текста, канал и статус поста. В ячейке видны первые два поста. Нажмите на дату или «Ещё», чтобы открыть полный список публикаций дня с учётом текущих фильтров. Кнопка «+» добавляет пост на выбранный день.
- Вид «Список» показывает публикации выбранного месяца. Доступны фильтры по каналу и статусу, поиск по тексту и названию канала. Счётчики запланированных и опубликованных постов относятся к выбранному месяцу и каналу.
- Вид «Черновики» показывает все серверные черновики выбранного канала, включая посты без даты. Ограничения в пять строк нет; доступен поиск.
- Статус «Ошибка публикации» в виде «Список» показывает ошибки за всё время, чтобы не потерять пост из другого месяца. Плашка «Требуется внимание» ведёт в этот список или в проверку каналов.
- На телефоне при первом открытии страницы выбран «Список». Переключиться на календарь можно вручную.
- Опубликованный или отправляющийся пост открывается для просмотра. Опубликованный пост можно открыть в соцсети по сохранённой ссылке.
- Данные обновляются раз в 30 секунд и при возвращении на вкладку браузера.

## Редактор и сохранение текста

- В форме поста выберите канал сверху. Под текстом находится строка для фото. На широком экране предпросмотр справа, его можно скрыть. На узком экране он открывается во вкладке «Предпросмотр». В нижней панели нажмите на время, чтобы изменить расписание или выбрать «Сейчас». Основная кнопка изменится на «Опубликовать» и откроет подтверждение отправки. Если загрузка фото недоступна, в блоке указана причина.

- Начните новый пост кнопкой «Новый пост» или «+» у даты. Выберите канал перед отправкой или сохранением на сервере. Один пост относится к одному каналу.
- Незавершённый текст сохраняется в локальном хранилище браузера отдельно для каждого аккаунта. На одном устройстве хранится один незавершённый пост; синхронизации с другими устройствами нет. Если браузер запрещает запись, интерфейс показывает предупреждение.
- При возвращении на страницу плашка предлагает продолжить незавершённый пост или удалить его. Перед заменой незавершённого текста другим постом интерфейс запрашивает подтверждение.
- Закрытие изменённого редактора требует подтверждения. При закрытии страницы браузер также предупреждает о несохранённых изменениях.
- Кнопка «Сохранить черновик» сохраняет пост на сервере, если выбран канал с доступом к публикации. Новый пост без такого канала можно сохранить только на устройстве. Для публикации его нужно восстановить, подключить или выбрать канал и сохранить на сервере.
- Перед немедленной публикацией открывается подтверждение с текущим текстом и выбранным каналом. Затем редактор сохраняет текущую версию поста и отправляет её: несохранённые изменения текста или канала не теряются при отправке.
- После успешного сохранения на сервере, публикации или удаления поста его локальная копия убирается.

Если за время работы с локальной копией исходный пост уже отправлен или отправляется, восстановление создаёт новый черновик с прежним несохранённым текстом. Опубликованный оригинал не меняется.

## Время

- Пользователь вводит дату и время в своём часовом поясе; браузер отправляет `scheduledAt` в UTC и `timeZone` (IANA).
- На странице подписаны текущий часовой пояс и смещение относительно UTC; календарь и карточки показывают местное время.
- Сервер хранит `scheduledAt` в UTC, поэтому переход на летнее время не меняет сохранённое время.

## Форматирование и отправка

- В ВК доступна разметка: `**жирный**`, `_курсив_`, `` `код` ``, `[текст](ссылка)`, списки `- `, цитаты `>`.
- В Telegram текст оформляется прямо в редакторе. Выделите фрагмент и выберите жирный, курсив, подчёркивание, зачёркивание или ссылку. Список и цитата применяются к строке. Текст из буфера вставляется без внешнего оформления.
- Старые черновики Telegram открываются с оформлением из Markdown. После редактирования сохраняются обычный текст и безопасная разметка Telegram. Счётчик в визуальном редакторе считает текст без тегов.
- Предпросмотр экранирует HTML. На широком экране текст и предпросмотр видны рядом, на узком — переключаются вкладками.
- При отправке в Telegram markdown преобразуется в HTML (`parse_mode: 'HTML'`): жирный, курсив, подчёркивание, зачёркивание, код, ссылки, цитаты; списки — строки с «•».
- Для ВК markdown преобразуется в формат стены: `**жирный**`, `*курсив*`, `__подчёркнутый__`, `~~зачёркнутый~~`, ссылки `[url|текст]`, списки с «•».
- Предпросмотр ВК показывает преобразованный текст для стены: сохраняет маркеры форматирования, заменяет `_курсив_` на `*курсив*`, цитаты — на строки с «—», убирает обратные кавычки кода. Ссылки с адресами HTTP/HTTPS отображаются как ссылки. Оформление Telegram не применяется к тексту ВК. Кнопки кода и цитаты для ВК недоступны.
- Лимит текста: 4 096 символов для Telegram, 16 000 для ВК.

## Автопубликация и ошибки

- Планировщик — `api/src/services/contentPlanScheduler.ts`, тик 30 секунд, блокировка в Redis на 2 минуты.
- `CONTENT_PLAN_SCHEDULER_ENABLED=0` выключает планировщик.
- Пост забирается атомарно: `scheduled → publishing`; повторный тик его не возьмёт.
- Успех: `published`, `publishedAt`, `externalPostId`, `externalUrl`.
- Ошибка: `failed` с текстом. При 429 — повтор через минуту, не больше трёх попыток. Остальные ошибки автоматически не повторяются.
- Ошибки прав бота помечают канал; недействительный токен помечает бота как `needs_reauth`.
- Ошибки ВК: истёкший токен и отсутствие `wall` — канал `needs_reauth`; нет прав/стена закрыта — `error`; код 6 — повтор через минуту.
- Bot API ходит через тот же SOCKS5, что и MTProto (`TELEGRAM_PROXY_*`). Ошибка `502 TELEGRAM_BOT_UNAVAILABLE` означает, что прокси/сеть недоступны с сервера, а не проблему с токеном.
- При сетевой ошибке неизвестно, дошло ли сообщение: пост помечается `failed` с просьбой проверить канал, автоповтора нет — защита от дублей.

## Фото для Telegram

- Укажите в окружении API имя закрытого бакета `CONTENT_PLAN_MEDIA_BUCKET` и статический ключ сервисного аккаунта (`CONTENT_PLAN_MEDIA_ACCESS_KEY`, `CONTENT_PLAN_MEDIA_SECRET_KEY`). Роль выдаётся на этот бакет. Оставьте версионирование выключенным. Разрешите в CORS метод POST и заголовок Content-Type для адресов фронтенда.
- Браузер получает подписанную форму на пять минут и загружает файл прямо в Yandex Object Storage. API принимает только метаданные. Бакет проверяет размер и заявленный тип, API проверяет метаданные объекта, а Telegram декодирует файл при отправке. Предпросмотр открывается как изображение с отдельного домена хранилища.
- Если добавлено фото, редактор ограничивает исходный текст подписи 1024 символами. Планировщик передаёт Telegram временную подписанную ссылку. Для опубликованного поста фото открывается по ссылке на публикацию.
- После подтверждения публикации Socstat удаляет файл. Если форма загрузки ещё действует или удаление не удалось, очистка повторяется планировщиком. Планировщик и Redis должны работать для повторов. Файлы без поста удаляются примерно через сутки, файлы неудачных публикаций — примерно через семь дней. Изображения в черновиках и расписании сохраняются.

## Фото для ВК

1. Создайте функцию Yandex Cloud Functions на Node.js с HTTPS-вызовом. Загрузите `deploy/functions/vk-photo/index.js`, укажите точку входа `index.handler` и таймаут 25 секунд. Для вызова по HTTPS без облачного IAM-токена разрешите публичный вызов функции. Обработчик проверяет подпись и срок действия каждого запроса до обращения к бакету или ВК.
2. В окружении функции задайте `CONTENT_PLAN_MEDIA_BUCKET` и `VK_PHOTO_RELAY_SECRET`. Используйте случайный секрет не короче 32 символов. В окружении API задайте тот же секрет как `CONTENT_PLAN_VK_PHOTO_RELAY_SECRET` и адрес функции `https://functions.yandexcloud.net/<id>` как `CONTENT_PLAN_VK_PHOTO_RELAY_URL`. Ключи бакета нужны только API. Для чтения фото функция получает подписанную ссылку.
3. Проверьте публикацию в тестовом сообществе с подключённым профилем администратора. Токен профиля должен работать с `photos.getWallUploadServer` и `photos.saveWallPhoto`. Ключ сообщества должен разрешать `wall.post` с вложением. При ошибке загрузки фото Socstat не отправляет запись без вложения.

Браузер загружает изображение в тот же бакет. Во время отправки функция переносит файл напрямую из бакета в ВК. API Socstat передаёт только ссылки и получает метаданные. Файл удаляется из бакета после подтверждения публикации по тем же правилам, что для Telegram.

## API

- `POST /api/content-plan/media/upload` — получить подписанную форму для JPEG или PNG.
- `POST /api/content-plan/media/confirm` — проверить наличие фото и вернуть временную ссылку для предпросмотра.
- `GET /api/content-plan` — каналы, посты, данные своего бота.
- `POST /api/content-plan/bot/telegram` — `{ token }`, проверить и сохранить бота.
- `DELETE /api/content-plan/bot/telegram` — отключить бота.
- `GET /api/content-plan/channels`.
- `POST /api/content-plan/channels/telegram` — `{ ref }`.
- `GET /api/content-plan/vk/groups` — группы, где пользователь админ.
- `POST /api/content-plan/channels/vk` — `{ groupId, token }`, ключ доступа сообщества.
- `DELETE /api/content-plan/channels/:id`.
- `POST /api/content-plan/posts`, `PATCH /api/content-plan/posts/:id`, `DELETE /api/content-plan/posts/:id`.
- `POST /api/content-plan/posts/:id/publish`.
- Все маршруты закрыты фичей `contentPlan`.

## Модели

- `ContentPlanBot` — бот пользователя: зашифрованный токен, `botId`, username, статус.
- `ContentPlanChannel` — канал: платформа, внешний id, `botId` для Telegram, `accessTokenEncrypted` для ВК, название, статус, права.
- `ContentPlanPost` — пост: канал, текст, статус, `scheduledAt` UTC, `timeZone`, `autoPublish`, внешний id/ссылка, попытки, ошибка.

## Ограничения этапа 4

- Один Telegram-бот на пользователя; несколько ботов не поддерживаются.
- ВК: только группы, где пользователь администратор. Фото требуют настроенной облачной функции и доступа приложения ВК к загрузке фото. Личная стена не поддерживается.
- В Telegram и в настроенном ВК можно приложить одно фото JPEG или PNG до 5 МиБ. Другие вложения не поддерживаются.
- Идеи ИИ в разделе не используются.
- Без подключённого канала новый черновик доступен только на текущем устройстве. Локальное хранилище содержит один незавершённый пост для аккаунта; очистка данных браузера удаляет эту копию.
- Лимитов на количество постов нет.
- Для ВК нужен ключ доступа сообщества с правом управления; ключ можно отозвать в настройках сообщества. Поведение `wall.post` с таким ключом не описано в официальной документации VK, поэтому его нужно проверять на тестовой группе.
