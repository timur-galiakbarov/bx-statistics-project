# Конкуренты

На странице аналитики сообщества VK, канала YouTube или Telegram доступен блок «Ваши конкуренты». Пользователь с активным доступом сохраняет до пяти конкурентов с любой из трёх платформ, отдельно для каждого исходного сообщества. На главной виджет «Конкуренты» показывает все наборы и отслеживаемые источники без конкурентов; строка ведёт на вкладку сравнения этого сообщества. Наборы хранятся в MongoDB (`CompetitorSet`), а не в браузере.

## Данные

Сравнение за последние 7/30 дней использует действующий сервис аналитики: подписчики, ER, публикации в неделю и средние просмотры публикации. Ошибки источников выводятся по строкам. Неполные выборки не участвуют в сравнении метрик публикаций. Лучшие публикации — одна наиболее просматриваемая среди загруженных для каждого конкурента.

Рост аудитории считается от среза точно на дату начала периода до текущего публичного числа подписчиков. Без исходного среза выводится пропуск; при нулевой базе процент не рассчитывается. Инсайт сравнивает процентный рост только источников с доступной базой. Ночные срезы делаются по Москве, поэтому это изменение от утреннего среза, а не от полуночи. ER Telegram считается по просмотрам; VK/YouTube — по подписчикам, поэтому место по ER и лучший ER определяются только среди источников с той же базой, что у исходного сообщества; остальные значения ER помечаются звёздочкой.

Поиск при вводе идёт автоматически по ссылкам любой платформы, по `@username` (Telegram и YouTube) и по названию во ВКонтакте. Поиск по названию на YouTube (100 единиц квоты) и username в Telegram запускаются явной кнопкой. Подсказки «похожие» — поиск во ВКонтакте по названию исходного сообщества.

## API

Все маршруты требуют авторизации и активного доступа:

- `GET /api/competitors/:platform/:id` — набор текущего пользователя.
- `GET /api/competitors` — непустые наборы пользователя с числом конкурентов и сохранённой сводкой (для главной).
- `POST /api/competitors/:platform/:id` — замена набора, тело `{ "competitors": [{ "platform": "telegram", "externalId": "rbc_news", "name": "Название" }], "sourceName": "Моё сообщество" }`. Без `platform` конкурент считается на платформе исходного сообщества. Пустой массив удаляет набор.
- `GET /api/competitors/:platform/:id/report?period=week|month` — сравнение исходного сообщества и сохранённых конкурентов. Отчёт за 30 дней сохраняет в набор сводку `summary` — место по просмотрам, ER и росту, — чтобы главная не ждала живую загрузку.

Идентификаторы: положительный цифровой ID VK, ID канала UC… YouTube, username Telegram. Сервер проверяет платформу, идентификаторы, дубли (по платформе и ID), собственный источник и лимит пяти. Источники отчёта загружаются параллельно, не более трёх одновременно.

## Развёртывание

Новая коллекция и индексы создаются обычным механизмом Mongoose, переноса данных не требуется: у конкурентов из старых наборов без `platform` используется платформа набора. Действующий `startSnapshotScheduler` / `snapshots:run` теперь включает исходные сообщества и конкурентов из сохранённых наборов, с дедупликацией по платформе и ID. Отдельный cron не нужен. Существующие настройки, токены и доступность API платформ необходимы, как и для остальных срезов. После удаления набора сбор прекращается, если источник не нужен другим наборам или сохранённым каналам; уже накопленная история остаётся.

История не восстанавливается задним числом. Проверка после развёртывания: сохранить конкурента, обновить страницу, проверить независимость набора в другом аккаунте, запустить обычный сбор срезов и проверить появление источников в покрытии. Проверить отказ шестому конкуренту, удаление, переключение 7/30 дней и строку недоступного сообщества.
