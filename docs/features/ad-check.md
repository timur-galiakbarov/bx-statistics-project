# Проверка канала перед покупкой рекламы

Вкладка «Перед рекламой» в аналитике VK, Telegram и YouTube помогает оценить просмотры публикаций и стоимость размещения. Доступна там же, где полный отчёт аналитики: на активном тарифе/триале и для бонусных источников VK. В кратком отчёте VK показывается описание функции с переходом к оплате. Прямые ссылки используют `section=advertising` вместе с обычными параметрами `platform`, `groupId` или `channel`.

## Источники данных

- Текущие публикации и подписчики — из уже загруженной аналитики платформы. Новые запросы к платформам не добавляются.
- Просмотры в одинаковом возрасте — `GET /api/snapshots/posts?platform=…&id=…&days=90`. Отбираются публикации выбранного периода по дате в Москве; если период начинается более 90 дней назад, интерфейс предупреждает об ограничении.
- Динамика аудитории — существующий `SubscriberHistoryPanel` и `/api/snapshots/history`, с обозначением доступного начала истории и пропусков.

Срезы начинают накапливаться после первого успешного анализа источника. Прошлые счётчики восстановить нельзя. Ошибка срезов выводится отдельно с кнопкой повтора; текущая аналитика остаётся доступна. Ответы устаревших запросов игнорируются при смене источника. Смена источника или периода очищает введённую цену и целевой CPM.

## Расчёты

- Выбор срока: 24, 48 (по умолчанию) или 72 часа. Для каждого срока строится собственная выборка из ненулевых по наличию срезов: числовое значение `0` учитывается, `null`, отсутствующие и некорректные значения исключаются.
- Значение просмотров на сроке уже вычислено сервером из ночных срезов с линейной интерполяцией (`viewsAtHour`), поэтому это оценка, а не точный замер в момент окончания срока.
- Медиана и 25-й/75-й процентили считаются непосредственно по значениям выбранной выборки. Квантили интерполируются линейно между соседними значениями. Минимум — три публикации. Менее десяти публикаций отмечаются как небольшая выборка.
- Разброс — центральные 50% значений, не гарантированный диапазон будущего размещения. Если `(P75 − P25) / медиана >= 1`, интерфейс предупреждает о заметной вариативности.
- CPM = полная цена размещения / медиана просмотров × 1000. Диапазон CPM: цена / P75 × 1000 … цена / P25 × 1000. При нулевом знаменателе соответствующий расчёт недоступен.
- Ориентир цены = целевой CPM × медиана / 1000. Целевой CPM задаёт сам пользователь; универсальной оценки «дёшево/дорого» нет.
- Деньги: положительная сумма до 1 млрд рублей, максимум два знака после запятой/точки; пробелы при вставке суммы допускаются. Неверный ввод отмечается и не участвует в расчёте. Суммы хранятся только в состоянии страницы.
- Контекст текущих публикаций: посты старше 72 часов с известными просмотрами. Медиана — минимум три поста; ER = сумма действий / сумма просмотров × 100. Действия: VK — лайки, комментарии, репосты; Telegram — реакции, комментарии, пересылки; YouTube — лайки и комментарии. Если необходимые действия недоступны хотя бы у одного поста, ER не рассчитывается. Эти накопительные метрики не подменяют просмотры на выбранном сроке в CPM.

## Ограничения и UX

Обычный контент и реклама входят в общую выборку: надёжной универсальной разметки рекламных публикаций нет. Список показывает до восьми последних публикаций, участвовавших в расчёте, с переходом к оригиналу. Просмотры не равны уникальным зрителям. Функция не подтверждает отсутствие накрутки и не прогнозирует продажи, подписки или успешность рекламы. Для YouTube общий контент канала не обязательно отражает просмотры рекламной интеграции.

Неполная выборка VK/YouTube отмечается по `wall.isComplete`. Telegram не отдаёт признак полноты, поэтому показывается отдельное пояснение об ограничениях загрузки. Ежедневные срезы также могут покрывать лишь часть публикаций.

В конце отчёта — вопросы владельцу о прошлых рекламных постах, формате, времени выхода, сроке удаления, закреплении, аудитории и отчётности. Карточки и переключатели соответствуют существующей аналитике Socstat; на узких экранах калькулятор перестраивается в одну колонку. Поля имеют подписи, пояснения, состояния ошибки и видимый фокус; результат объявляется через `aria-live`.

## Код и проверка

- `src/components/AdCheckPanel.tsx` — общий интерфейс, загрузка срезов, калькулятор и примеры.
- `src/utils/adCheck.ts` — расчёты, фильтрация и разбор сумм; `adCheck.test.ts` — проверки границ и формул.
- `src/pages/AnalyticsPage.tsx`, `src/pages/TelegramPage.tsx` — вкладки и нормализация данных.
- `src/components/AnalyticsPreview.tsx` — описание функции в кратком отчёте.
- `src/styles.css` — оформление и мобильная адаптация.

Новых переменных окружения, коллекций и миграций нет. Требуется существующая инфраструктура ежедневных срезов (см. [snapshots.md](snapshots.md)). Проверки: `npm test`, `npm run build`; вручную проверить ввод цены, переключение 24/48/72 ч, смену периода/канала, недостаточную историю, нулевые просмотры, ошибку срезов и повтор, доступ без тарифа и мобильный экран.

При реализации прошли 55 тестов (47 существующих и 8 новых), проверка типов и production-сборка. Браузерные проверки в Chromium на тестовых ответах API: все три платформы, цена и целевой CPM, переключение срока, некорректные суммы, экраны 320/390/768/1440 px без переполнения страницы, клавиатурный переход между полями, доступное состояние выбранного срока, очистка калькулятора при смене периода, сохранение вкладки после обновления, отсутствие срезов, нулевые просмотры, ошибка с повтором, краткий отчёт VK и истёкший доступ Telegram. Скриншоты широкого и мобильного экрана просмотрены визуально. Работа с реальными API платформ на production в этой проверке не запускалась.
