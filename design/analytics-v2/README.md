# Макеты «Аналитика v2»

Дизайн-макеты к 13 задачам двух спринтов из разбора страницы `/analytics` (VK, Telegram, YouTube). План работ — [docs/analytics-v2-plan.md](../../docs/analytics-v2-plan.md).

- [board.html](board.html) — доска: каждая задача отдельно (макет + назначение + источник данных + состояния).
- [screens.html](screens.html) — три экрана целиком: VK «Сводная», Telegram «Сводная», YouTube «Обзор», новые блоки стоят на своих местах.
- `screenshots/` — растровые версии (`board.png`, `screens.png`, `vk.png`, `telegram.png`, `youtube.png`), сняты headless Chrome.

Открыть: двойной клик по HTML-файлу или `open design/analytics-v2/board.html`. Внешних зависимостей нет — один локальный CSS, без шрифтов из сети и без JS.

Цифры в макетах демонстрационные (сообщество «Мой и твой Воронеж», 12 400 подписчиков). Структура блоков, подписи и состояния — настоящие, под текущие данные API.

## Спринт 1 — данные уже есть

| № | Задача | Где | Источник |
|---|---|---|---|
| T1 | Δ к прошлому периоду на Telegram и YouTube | Сводная · Обзор | `previous` уже считается в API |
| T2 | Подписки/отписки по дням + чистый прирост | Динамика подписчиков | `partnerStats` → `subscribe_action` / `unsubscribe_action` |
| T3 | Охват: всего / подписчики / виральный | Сводная | `reach.all` / `reach.subscribers` / `reach.viral` |
| T4 | Охват, сохранения, скрытия, клики, подписки у поста | Посты | `partnerStats.getContentStatsByPeriod` |
| T5 | Клипы и истории | новая вкладка «Контент» | `content_type: clip / story` |
| T6 | Метрики поста на одинаковом возрасте (7 дней) | Сводная · Аудитория | `PostSnapshot` + кривая 24/48/72 ч |
| T7 | YouTube: подписчики и просмотры канала в KPI | Обзор | `ChannelSnapshot` (+ поле просмотров канала) |

## Спринт 2 — расчёты на своих данных

| № | Задача | Где | Источник |
|---|---|---|---|
| T8 | Лучшее время публикации | Посты · новая панель | посты за 90 дней (дата, время, ER) |
| T9 | Частота публикаций против охвата | Посты | недельные корзины за 90 дней |
| T10 | Рейтинг форматов с медианами | Посты | `contentType` + охват постов |
| T11 | Виральность и качество распространения | Сводная · Аудитория | `reach.viral`, `shares`, `subscriptions`, кривые |
| T12 | Бенчмарк с похожими сообществами | Сводная | снимки по всем источникам, размерная группа |
| T13 | План, цель и алерты отклонений | Сводная + VK-дайджест | цель источника + медиана 30 дней |

## Идеи, на которых держатся макеты

1. **Ничего нового в визуальном языке.** Те же панели, KPI с тенью, зелёный акцент, серые подписи, Roboto. Новые блоки не должны выглядеть как другая страница.
2. **У каждой метрики есть «против чего».** Дельта к прошлому периоду, медиана похожих, собственная норма за 30 дней. Цифра без базы не показывается.
3. **Честные состояния.** Нет прав — объясняем почему; нет истории — говорим с какой даты появится; мало данных — приглушаем вывод. Нигде нет нуля вместо «неизвестно».
4. **Ответ, а не дашборд.** В каждом блоке одна мысль и одно действие: «видео — сильный формат, добавьте 1–2 в план», «3 дня без публикаций».
5. **Метки T1–T13** на экранах и на доске совпадают, чтобы обсуждать задачу, не пересказывая вёрстку.

## Что в макетах не покрыто

- **Мобильная адаптация.** По данным выгрузки мобильных визитов 13%, но именно там отчёт сейчас неудобен. Нужен отдельный проход: KPI в 2 колонки, таблицы в карточки, теплокарта в горизонтальный скролл.
- **Тёмная тема** — в продукте её нет, макеты не вводят.
- **Ошибки загрузки и таймауты VK** — показан только сценарий «нет охвата», остальные состояния стоит добавить на этапе вёрстки.
- **Пустые состояния для каждого блока** — описаны в аннотациях, но нарисован только один пример (вкладка «Истории»).

## Перерендерить картинки

```bash
cd design/analytics-v2
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --headless=new --no-sandbox --disable-gpu --hide-scrollbars \
  --user-data-dir=/tmp/socstat-home/chrome --force-device-scale-factor=1 \
  --window-size=1500,12000 --screenshot=screenshots/board.png "file://$PWD/board.html"
```

Скриншот снимается в 1500 px по ширине; лишний фон снизу обрезается. Для ретины добавить `--force-device-scale-factor=2`.
